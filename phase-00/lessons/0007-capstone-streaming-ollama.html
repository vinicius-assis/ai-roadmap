Fase 0 · Lição 7 · Capstone · ~40 min

Capstone: streaming de tokens de um modelo local

Um script TS que consome um LLM real, token a token, com timeout e temperature. A semente da Fase 1.

Todo produto de LLM que parece "responder enquanto pensa" está fazendo uma coisa: lendo um corpo HTTP que chega aos poucos e imprimindo cada pedaço na hora. Nesta lição você junta as quatro peças da Fase 0 — for await...of, timeout defensivo, async/await e temperature — num único arquivo que fala com um modelo de verdade rodando na sua máquina. Na Fase 1 você troca localhost por uma API paga e o resto do código continua igual.

1. O Ollama é um servidor HTTP local

Depois de ollama serve (ou o app aberto), existe um servidor em http://localhost:11434. O endpoint que interessa é POST /api/chat. O corpo da requisição: 

{
  "model": "qwen2.5:0.5b",
  "messages": [{ "role": "user", "content": "explique o que é um vetor" }],
  "stream": true,
  "options": { "temperature": 0.8 }
}

Com stream: true a resposta é NDJSON — um objeto JSON por linha, separados por \n. Cada linha: 

{"message":{"role":"assistant","content":"Um"},"done":false}
{"message":{"role":"assistant","content":" vetor"},"done":false}
{"message":{"role":"assistant","content":" é"},"done":false}
...
{"message":{"role":"assistant","content":""},"done":true,"done_reason":"stop"}

O texto do token está em message.content. Quando done vira true, acabou. É o mesmo padrão mental do SSE da Lição 2, só que a fronteira é \n em vez de \n\n e não tem o prefixo data:. (docs da API do Ollama)

2. Os bytes não chegam alinhados por linha

res.body é um stream de pedaços de bytes, não de linhas. Um pedaço pode terminar no meio de um JSON: 

pedaço 1:  {"message":{"content":"Um"},"done":false}\n{"message":{"con
pedaço 2:  tent":" vetor"},"done":false}\n

A técnica padrão é um buffer de texto: acumule o que chegou, corte em \n, processe as linhas completas, e guarde a última fatia (que pode estar pela metade) de volta no buffer pra próxima volta. 

let buffer = "";
for await (const bytes of res.body) {
  buffer += decoder.decode(bytes, { stream: true });
  const linhas = buffer.split("\n");
  buffer = linhas.pop() ?? "";        // ← a incompleta volta pro buffer
  for (const linha of linhas) { /* JSON.parse(linha) */ }
}
Por quê { stream: true } no decode? Um caractere multibyte (acento, emoji) também pode ser cortado entre dois pedaços. Essa flag faz o TextDecoder segurar os bytes soltos até completar.

3. Empacote como um async generator

Esconda os bytes, o buffer e o JSON.parse dentro de uma função que só yielda strings de token — igual ao stream() da Lição 2. Quem chama nem sabe que é HTTP: 

async function* streamChat(prompt: string, opts): AsyncGenerator<string> { ... }

for await (const token of streamChat("me conte uma piada", { temperature: 1.2 })) {
  process.stdout.write(token);
}

O temperature entra em options no corpo — é literalmente o número que a Lição 6 dividia nos logits, só que agora o servidor faz a conta. E o timeout da Lição 3 vira uma linha: signal: AbortSignal.timeout(60_000).

Por que guardar a última fatia do split("\n") de volta no buffer?

B. O stream entrega bytes, não linhas. A última fatia depois do split quase sempre é um JSON incompleto — processá-la agora daria JSON.parse com erro. Ela espera o próximo pedaço completá-la.

O que você vai saber fazer ao fim

  • consumir um corpo HTTP streamado em TS: bytes → buffer → linhas → objetos;
  • explicar a fronteira NDJSON e por que o buffer é necessário;
  • embrulhar tudo num async generator que só entrega tokens;
  • passar temperature e um timeout numa chamada real e ver o efeito no terminal.

Prática (40 min) — pratice-07.ts

Objetivo: um script que faz streaming de uma resposta do qwen2.5:0.5b pro terminal, token a token, duas vezes — com temperature baixa e alta — pra você ver a diferença ao vivo.

Confira antes: curl http://localhost:11434/api/tags deve listar o modelo. Se não, rode ollama pull qwen2.5:0.5b.

Duas realidades do modelo local. (1) A primeira chamada carrega o modelo na RAM — pode levar 30–60 s numa máquina sem GPU; por isso o timeout aqui é 60 s, não 5 s. (2) Um modelo de 0,5 B tagarela e às vezes entra em loop de lista numerada infinita — options.num_predict corta a resposta num teto de tokens. Sem ele, só o timeout te salva (e é bom ver isso acontecer uma vez). 
async function* streamChat(
  prompt: string,
  opts: { temperature?: number } = {},
): AsyncGenerator<string> {
  const res = await fetch("http://localhost:11434/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      // TODO 1: model: "qwen2.5:0.5b", messages (role user + prompt), stream: true,
      //         options: { temperature: opts.temperature ?? 0.8, num_predict: 60 }
    }),
    signal: AbortSignal.timeout(60_000),
  });
  if (!res.ok) throw new Error(`Ollama ${res.status}`);

  const decoder = new TextDecoder();
  let buffer = "";
  for await (const bytes of res.body as AsyncIterable<Uint8Array>) {
    buffer += decoder.decode(bytes, { stream: true });
    const linhas = buffer.split("\n");
    buffer = linhas.pop() ?? "";
    for (const linha of linhas) {
      if (!linha.trim()) continue;
      const obj = JSON.parse(linha);
      // TODO 2: se obj.message?.content, yield ele
      // TODO 3: se obj.done, return
    }
  }
}

async function main() {
  const prompt = "Em uma frase, o que é uma similaridade de cosseno?";
  for (const T of [0.2, 1.3]) {
    console.log(`\n\n--- temperature ${T} ---`);
    // TODO 4: for await (const token of streamChat(prompt, { temperature: T }))
    //         → process.stdout.write(token)
  }
  console.log();
}

main();   // não esqueça

Conceitos a segurar (não é decoreba de ordem):

  • O generator é lazy. Chamar streamChat(...) não dispara o fetch — o corpo só roda quando o for await pede o primeiro token.
  • yield devolve e pausa. Cada token sai, a função congela ali, e só descongela quando o loop pede o próximo. É o streaming.
  • return dentro do generator encerra o for await. Por isso obj.done → return fecha tudo limpo.
  • AbortSignal.timeout aborta o fetch inteiro. Se estourar 30 s, o for await lança TimeoutError — trate com try/catch se quiser mensagem amigável.

--- temperature 1.3 ---

O texto sai aparecendo aos poucos, não de uma vez — é a prova de que o streaming funciona. Cortado no meio da frase porque num_predict: 60 limitou.
