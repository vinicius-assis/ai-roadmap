Fase 0 · Lição 5 · ~30 min

Vetores, produto escalar e similaridade de cosseno

A matemática que faz a busca semântica funcionar — à mão e em TypeScript.

Um embedding é um vetor: uma lista de números que a rede neural escolheu pra representar o significado de um texto. "cachorro" e "cão" viram vetores quase iguais; "cachorro" e "planilha" viram vetores bem diferentes. Todo sistema de RAG e busca semântica que você vai construir nas próximas fases faz a mesma pergunta milhares de vezes: quão parecidos são estes dois vetores? A resposta é a similaridade de cosseno, e ela é feita de duas peças: o produto escalar e a norma.

1. Um vetor é uma direção no espaço

Esqueça "seta na aula de física" por um segundo. Para nós, um vetor é só um number[]: [0.2, -1.3, 0.8]. Cada número é uma coordenada em um eixo. Com 2 números você aponta pra algum lugar num plano; com 3, num espaço; os embeddings da OpenAI têm 1536 números — 1536 eixos, impossível de desenhar, mas a matemática é idêntica à de 2D.

Duas coisas nos interessam num vetor: pra onde ele aponta (direção) e quão longe ele vai (comprimento). Para significado, só a direção importa.

2. Produto escalar: a · b

Multiplique os vetores componente a componente e some tudo. É um número só (um "escalar", daí o nome). 

a = [1, 2, 2]
b = [2, 0, 1]

a · b = (1·2) + (2·0) + (2·1) = 2 + 0 + 2 = 4

Intuição: o produto escalar é grande e positivo quando os dois vetores apontam pro mesmo lado, perto de zero quando são perpendiculares (nada a ver um com o outro), e negativo quando apontam pra lados opostos. (3Blue1Brown — Dot products)

Mas o produto escalar sozinho tem um defeito: ele também cresce quando os vetores ficam mais compridos, não só mais alinhados. Precisamos tirar o comprimento da conta.

3. Norma: o comprimento de um vetor

A norma (ou magnitude) ‖a‖ é o comprimento do vetor — Pitágoras em N dimensões: eleve cada componente ao quadrado, some, tire a raiz. 

‖a‖ = √(1² + 2² + 2²) = √9 = 3
‖b‖ = √(2² + 0² + 1²) = √5 ≈ 2.236

4. Similaridade de cosseno: produto escalar normalizado

Divida o produto escalar pelos dois comprimentos. O resultado é o cosseno do ângulo entre os vetores — puro alinhamento, sem influência do tamanho. 

cos(a, b) = (a · b) / (‖a‖ · ‖b‖)
          = 4 / (3 · 2.236)
          ≈ 0.596

Fonte: Wikipedia — Cosine similarity: "é o produto escalar dos vetores dividido pelo produto dos seus comprimentos."

cos(a, b) Ângulo Significado
+10°mesma direção — sentido praticamente idêntico
090°perpendiculares — sem relação
−1180°opostos
Na prática: embeddings de texto quase nunca dão negativo. Os valores úteis ficam tipicamente entre ~0.7 (frouxamente relacionados) e ~0.95 (praticamente o mesmo assunto). Você ordena candidatos por cosseno e pega os top-k.
Atalho que os provedores te dão: a OpenAI e a maioria dos modelos devolvem embeddings já normalizados (‖v‖ = 1). Quando os dois vetores têm comprimento 1, o denominador vira 1 · 1 e a similaridade de cosseno é só o produto escalar. Por isso bancos vetoriais falam em "inner product" e "cosine" quase como sinônimos — pra vetores unitários, são a mesma coisa.

Confira sua conta

Digite vetores e veja cada passo. Comece com a = 1,2,2 e b = 2,0,1 (deve bater com a lição). Depois teste a = 3,0 e b = 30,0 — mesmo cosseno (1) apesar de comprimentos bem diferentes.

Por que dividir o produto escalar pelas duas normas dos vetores?

B. O produto escalar cru aumenta tanto quando os vetores se alinham quanto quando ficam mais compridos. Dividir por ‖a‖·‖b‖ cancela o comprimento e sobra o cosseno do ângulo — alinhamento puro, de −1 a +1.

Os embeddings já vêm normalizados. O que a similaridade de cosseno vira?

A. Normalizado quer dizer ‖v‖ = 1. O denominador ‖a‖·‖b‖ vira 1·1 = 1, então cos(a,b) = a · b. Cálculo mais barato — por isso os provedores normalizam pra você.

Revisão espaçada (Lição 3/4): num loop de retry, chega um 404. Você repete com backoff? — Não: 4xx (fora do 429) é erro permanente, repetir dá o mesmo 404. Só 429 e 5xx + rede/timeout merecem retry.

Sua vitória de hoje

  • calcular um produto escalar e uma norma à mão;
  • montar a similaridade de cosseno a partir dessas duas peças;
  • explicar por que é cosseno e não produto escalar cru — e quando dá na mesma;
  • implementar as três funções em TypeScript e ranquear textos por similaridade.

Prática (20 min) — pratice-05.ts

Objetivo: implementar a similaridade de cosseno e usá-la pra achar, dado um vetor de consulta, qual "documento" é o mais parecido — o coração de um retriever de RAG.

  1. dot. function dot(a: number[], b: number[]): number — some a[i] * b[i]. (Assuma mesmo tamanho.)
  2. norm. function norm(v: number[]): number — Math.sqrt da soma dos quadrados. Dica: dot(v, v) já é a soma dos quadrados.
  3. cosine. function cosine(a: number[], b: number[]): number — dot(a, b) / (norm(a) * norm(b)).
  4. Ranquear. Dado um array de docs e uma consulta: 
    const docs = [
  { texto: "como treinar um cachorro filhote", v: [0.9, 0.1, 0.0] },
  { texto: "receita de bolo de cenoura",       v: [0.0, 0.2, 0.9] },
  { texto: "adestramento canino para iniciantes", v: [0.8, 0.2, 0.1] },
];
const consulta = [0.85, 0.15, 0.05];
    Calcule o cosseno da consulta contra cada doc.v, ordene do maior pro menor e imprima texto + score (3 casas).
  5. Confirme o atalho. Escreva function unit(v) que divide cada componente por norm(v). Normalize consulta e todos os doc.v, e verifique que dot(unit(a), unit(b)) dá (quase) o mesmo que cosine(a, b).

Saída esperada (aproximada)

como treinar um cachorro filhote       0.996
adestramento canino para iniciantes   0.995
receita de bolo de cenoura            0.094

atalho confere: cosine = 0.996, dot(unit,unit) = 0.996

Os números exatos dependem dos vetores; a ordem e a ordem de grandeza é o que importa. Lembre de chamar main() no fim. Rode com npx tsx pratice-05.ts e me mande.
