Amostragem: temperature e top_p

O que os "botões de criatividade" da API de LLM realmente fazem com os números.

A cada token, o modelo não te devolve uma resposta — ele devolve uma distribuição de probabilidade sobre todo o vocabulário (~100 mil tokens). Quem escolhe o próximo token a partir dessa distribuição é o amostrador (sampler), e você o controla por dois parâmetros: temperature e top_p. Saber o que eles fazem é a diferença entre "por que o modelo alucina/repete/fica sem graça?" ser um mistério ou um botão que você ajusta. No capstone (Lição 7) você vai passar temperature numa chamada real.

1. De logits a probabilidades: softmax

A última camada do modelo cospe um número bruto por token — o logit. Logits não são probabilidades (podem ser negativos, não somam 1). A função softmax os converte: exponencia cada um e divide pela soma. 

p_i = exp(logit_i) / Σ_j exp(logit_j)

Exponenciar amplifica as diferenças: um logit um pouco maior vira uma probabilidade bem maior. O token de maior logit sempre vira o de maior probabilidade.

2. temperature: achata ou afia a distribuição

temperature (T) é um divisor aplicado aos logits antes do softmax: 

p_i = softmax(logit_i / T)

Fonte: Hugging Face — How to generate text, de Patrick von Platen.

  • T < 1 — divide por menos que 1, então aumenta as diferenças entre logits. A distribuição fica mais afiada: o token mais provável domina. Mais previsível, mais repetitivo.
  • T → 0 — o maior logit domina totalmente. Vira greedy decoding: sempre o token nº 1. Praticamente determinístico.
  • T = 1 — usa a distribuição exatamente como o modelo a produziu.
  • T > 1 — achata a distribuição, dá chance a tokens improváveis. Mais diverso, mas passa do ponto e vira incoerência.
Faixas variam por provedor. Na API da Anthropic, temperature vai de 0.0 a 1.0 (padrão 1.0). Na OpenAI, de 0 a 2 (padrão 1). Mesmo com T = 0 a saída não é 100% garantida — ainda há não-determinismo de hardware/execução.

3. top_p (nucleus sampling): corta a cauda

Depois do softmax, ordene os tokens do mais provável pro menos. top_p mantém só o menor conjunto do topo cuja probabilidade acumulada chega a p, e joga fora o resto (a "cauda" de tokens improváveis). Depois renormaliza. 

top_p = 0.9  →  vá somando p_i do maior pro menor;
                pare quando a soma passar de 0.9;
                amostre só entre esses tokens.

O truque: o tamanho do conjunto se adapta. Quando o modelo está confiante (um token com 95%), o núcleo tem 1–2 tokens. Quando está em dúvida (probabilidades espalhadas), o núcleo cresce. (HF — nucleus sampling)

  • top_p = 1.0 — não corta nada (padrão).
  • top_p = 0.9 — corte suave, remove tokens absurdos, mantém variedade.
  • top_p = 0.1 — só a nata; quase greedy.
Primo: top_k mantém os k tokens mais prováveis (número fixo). top_p costuma ser melhor porque o k ideal muda a cada token.
Regra prática (Anthropic): ajuste temperature primeiro e só mexa em top_p se precisar de controle fino. Desde o Opus 4.1 a Anthropic não deixa você mandar os dois na mesma chamada — os dois remodelam a mesma distribuição e empilhá-los é difícil de raciocinar. (Signal & Syntax — Temperature and Top-P)

Ponto de partida: ~0.0–0.3 pra extração/classificação/código, ~0.7 pra conversa, ~1.0+ pra brainstorm/escrita criativa.

Mexa nos botões

Vocabulário de brinquedo com 6 tokens e seus logits. Arraste temperature pra 0.3 — veja cachorro engolir tudo. Suba pra 1.8 — veja planilha e xícara ganharem chance real. Volte T pra 1 e baixe top_p pra 0.7 — veja a cauda ser cortada (riscada).

Você baixa temperature de 1.0 para 0.2. O que acontece com a distribuição?

B. temperature divide os logits antes do softmax. Dividir por 0.2 multiplica as diferenças por 5 — o maior logit fica muito à frente e o softmax concentra o peso nele. T → 0 é o limite: greedy, sempre o token nº 1.

Num passo, um token tem 0.95 de probabilidade. Com top_p = 0.9, quantos tokens entram no sorteio?

A. top_p soma as probabilidades do maior pro menor e para quando passa de p. Se o primeiro token já tem 0.95 ≥ 0.9, o núcleo é só ele. É isso que torna o top_p adaptativo: núcleo pequeno quando o modelo está confiante, grande quando está em dúvida.

Revisão espaçada (Lição 5): a = [1, 0], b = [0, 5]. Similaridade de cosseno? — a · b = 0, então cos = 0: perpendiculares, sem relação. O comprimento 5 de b não muda nada — é justamente o que a divisão pelas normas remove.

Prática (20 min) — pratice-06.ts

Objetivo: implementar o pipeline de amostragem — de logits crus até o token sorteado — e observar no terminal o efeito da temperature. É exatamente o que roda dentro do servidor do modelo a cada token.

  1. softmax. function softmax(logits: number[], T: number): number[] — divida cada logit por T, exponencie (Math.exp), divida pela soma. O array de saída deve somar 1.
    Conceito: subtraia Math.max(...scaled) de cada valor antes do exp — resultado idêntico, mas evita Infinity com logits grandes. (É o único "truque" aqui; o resto é a fórmula direta.)
  2. sample. function sample(probs: number[]): number — sorteie um índice respeitando as probabilidades. Padrão "roleta": const r = Math.random(), vá somando probs[i] num acumulador e retorne i no passo em que o acumulador passa de r.
  3. Observe a temperatura. Dado 
    const vocab  = ["cachorro", "gato", "filhote", "ração", "planilha"];
const logits = [2.0, 1.4, 0.9, 0.3, -1.2];
    Para cada T em [0.2, 0.7, 1.0, 1.8]: imprima as probabilidades (2 casas, %) e depois sorteie 1000 vezes com sample, imprimindo a contagem por token. As contagens devem seguir de perto as probabilidades.
  4. (Opcional) topP. function topP(probs: number[], p: number): number[] — zere os tokens fora do núcleo e renormalize o resto pra somar 1. Rode o teste de 1000 sorteios com T=1 e p=0.8 e confirme que os tokens da cauda saem 0 vezes.

Saída esperada (aproximada)

T=0.2  cachorro 94.9%  gato 4.7%  filhote 0.4%  ração 0.0%  planilha 0.0%
       sorteios: { cachorro: 949, gato: 47, filhote: 4, ração: 0, planilha: 0 }

T=1.0  cachorro 47.6%  gato 26.1%  filhote 15.8%  ração 8.7%  planilha 1.9%
       sorteios: { cachorro: 470, gato: 265, filhote: 152, ração: 92, planilha: 21 }

T=1.8  cachorro 34%    gato 25%    filhote 19%    ração 14%   planilha 7%

Os números exatos podem variar um pouco (e os sorteios mudam a cada execução — é aleatório). O que importa: a distribuição concentra quando T cai e espalha quando sobe, e as contagens seguem as probabilidades. Lembre de chamar main() no fim. Rode com npx tsx pratice-06.ts e me mande.
